# 项目命令

日常操作优先使用 `./scripts/atec-app`。以下命令用于环境检查、排错、单场处理和复现实验。

## 1. 常用入口

以下命令均在仓库根目录的终端中运行：

```bash
./scripts/atec-app
./scripts/atec-pipeline --help
./scripts/atec-pipeline status
```

## 2. 环境与资产检查

```bash
./scripts/atec-pipeline doctor
./scripts/atec-pipeline doctor --deep
./scripts/check_all_environments.sh
./scripts/verify_local_assets.sh
./scripts/bootstrap_third_party.sh --check
```

缺失第三方源码时：

```bash
./scripts/bootstrap_third_party.sh --install
```

## 3. 场次初始化、采集和标注

创建场次 Manifest：

```bash
./scripts/atec-pipeline init \
  projects/atec_real <scene> \
  --split train \
  --only-class <class> \
  --scene-class <class>
```

采集命令参数以帮助为准：

```bash
./scripts/atec-pipeline capture --help
```

对已保存场次执行分段、检查缺失 Mask 和完整处理：

```bash
MANIFEST=projects/atec_real/manifests/<scene>_<split>.yaml

./scripts/atec-pipeline segment "$MANIFEST"
./scripts/atec-pipeline checklist \
  projects/atec_real/data/scenes/<class>/<scene>/project_reports/segments.json
./scripts/atec-pipeline run "$MANIFEST"
```

单独打开 Mask 编辑器：

```bash
./scripts/atec-pipeline mask \
  /ABSOLUTE/PATH/rgb/000000.png \
  /ABSOLUTE/PATH/key_masks/<instance>/000000.png
```

## 4. 数据切分与验证

按完整场次准备验证集应优先使用 App。App 实际调用同一个统一 CLI，便于单独复现和 Debug：

```bash
DATASET=projects/atec_real/datasets/atec_yolo11_seg/dataset.yaml

# 自动预览，不修改数据
./scripts/atec-pipeline split "$DATASET" --auto

# 明确指定完整场次并执行
./scripts/atec-pipeline split "$DATASET" \
  --val-scenes <scene_a> <scene_b> \
  --apply
```

底层工具仍可独立调用：

```bash
"${ATEC_YOLO_PY:-$HOME/miniforge3/envs/yolo11/bin/python}" \
  tools/split_dataset_by_scene.py \
  --data "$DATASET" --auto
```

严格验证：

```bash
./scripts/atec-pipeline validate \
  projects/atec_real/datasets/atec_yolo11_seg/dataset.yaml
```

验证要求：

- 只允许 `accepted` 进入正式标签；
- train/val 不共享场次、采集会话或源视频；
- 标签类别 ID 合法；
- 未人工确认的空标签不能冒充负样本；
- 没有真实 test 时不写 `test:`。

## 5. YOLO11-seg 训练

App 训练按钮会调用同一后端。CLI：

```bash
./scripts/atec-pipeline train \
  projects/atec_real/datasets/atec_yolo11_seg/dataset.yaml \
  --init-mode baseline \
  --model models/yolo11s-seg.pt \
  --epochs 100 --patience 30 \
  --imgsz 640 --batch 4 --workers 4 \
  --device 0 --seed 0 --cache false \
  --project runs/segment \
  --name atec_9class_reviewed_20260829
```

完整可复现入口：

```bash
"${ATEC_YOLO_PY:-$HOME/miniforge3/envs/yolo11/bin/python}" tools/train_yolo11_seg.py \
  --data projects/atec_real/datasets/atec_yolo11_seg/dataset.yaml \
  --model models/yolo11s-seg.pt \
  --init-mode baseline \
  --epochs 100 --batch 4 --imgsz 640 --device 0 --workers 4 \
  --patience 30 --seed 0 --cache false \
  --require-project-reports --require-source-ids \
  --project runs/segment --name atec_9class_reviewed_20260829
```

入口固定启用 AMP 和 deterministic 训练。启动前必须确认目标目录不存在，避免覆盖历史结果：

```bash
test ! -e runs/segment/atec_9class_reviewed_20260829
```

只有该实验仍处于**未正常完成**状态时，才允许从同一 run 内的 `weights/last.pt` 恢复：

```bash
./scripts/atec-pipeline train \
  projects/atec_real/datasets/atec_yolo11_seg/dataset.yaml \
  --project runs/segment \
  --name atec_9class_reviewed_20260829 \
  --resume
```

`--resume` 会严格使用上述 run-local `last.pt`；正常完成并 strip 的 run 不能恢复，也不能用历史 4/5/7 类模型续训。训练中断时不得晋升 `best.pt`，应先完成同一 run 的恢复与验收。

当前九类默认模型：

```text
runs/segment/atec_9class_reviewed_20260829/weights/best.pt
```

正式数据共 5,883 个 accepted 图片/标签对，train 5,010、val 873。分类分布：

| 类别 | train | val |
|---|---:|---:|
| can | 349 | 82 |
| watermelon_rind | 764 | 65 |
| meal_box | 403 | 58 |
| red_paper_bag | 553 | 73 |
| blue_bin | 526 | 103 |
| green_bin | 461 | 87 |
| red_bin | 637 | 64 |
| purple_paper_bag | 721 | 189 |
| sand_bottle | 596 | 152 |

该模型从官方 `models/yolo11s-seg.pt` 全新初始化，不加载或续训旧 4/5/7 类 `best.pt`。训练请求最多 100 个 epoch、`patience=30`，因 EarlyStopping 自然结束于第 46 个 epoch，最佳为 epoch 16。最佳 epoch 的训练时 Mask 指标为 `P=0.94661`、`R=0.94623`、`mAP50=0.96001`、`mAP50-95=0.87029`；最终独立 full-val 验证为 `P=0.94597`、`R=0.94736`、`mAP50=0.96011`、`mAP50-95=0.87006`。训练环境为 Ultralytics `8.4.126`、Torch `2.6.0+cu124`。

历史权重和 run 全部保留，用于回滚和对照。新权重不进入 Git 历史，在 [ATEC 9-class reviewed model 2026-08-29](https://github.com/hezhou0331/yolo-annotation-pipeline/releases/tag/model-20260829) 中以 `atec-9class-reviewed-20260829-best.pt` 和同名 `.sha256` 发布；权重 SHA-256 为 `94cb56050f121d63e8219287a4c5d0c2108e30078015a6ed624765701b9dfc0f`，Release Notes 保留完整验收记录。

## 6. 实时识别

默认九类模型与外接摄像头：

```bash
./scripts/atec-live-yolo
```

指定模型或摄像头：

```bash
ATEC_YOLO_MODEL=/ABSOLUTE/PATH/best.pt \
ATEC_YOLO_SOURCE=0 \
ATEC_YOLO_CONF=0.25 \
./scripts/atec-live-yolo
```

完整命令：

```bash
"${ATEC_YOLO_PY:-$HOME/miniforge3/envs/yolo11/bin/python}" \
  tools/live_yolo11_seg.py \
  --model /ABSOLUTE/PATH/best.pt \
  --source 0 --conf 0.25 --imgsz 640 --device 0
```

## 7. xcx 候选与 A/B 实验

xcx 主要是检测模型，只能提供候选框或迁移初始化，不能直接生成 YOLO11-seg 像素标签。

生成候选但不覆盖正式 Mask：

```bash
./scripts/atec-pipeline propose \
  <manifest.yaml> \
  projects/atec_real/data/scenes/<class>/<scene>/project_reports/segments.json \
  --output <proposal_dir>
```

人工确认后晋升候选：

```bash
./scripts/atec-pipeline promote /ABSOLUTE/PATH/proposal.json <instance_id>
```

生成 A/B 计划：

```bash
"${ATEC_YOLO_PY:-$HOME/miniforge3/envs/yolo11/bin/python}" \
  tools/run_yolo11_seg_ab.py \
  --data projects/atec_real/datasets/atec_yolo11_seg/dataset.yaml
```

只有在相同 train/val、参数和现场误检测试下，xcx-transfer 稳定优于 baseline，才应替换正式初始化方式。

## 8. 迁移与回归

预览旧场景目录迁移：

```bash
/usr/bin/python3 tools/migrate_scene_layout.py \
  --project-root projects/atec_real
```

确认无冲突后执行：

```bash
/usr/bin/python3 tools/migrate_scene_layout.py \
  --project-root projects/atec_real --apply
```

提交前回归：

```bash
python3 -m py_compile atec_pipeline/*.py tools/*.py
git diff --check
./scripts/atec-pipeline smoke-test
```
