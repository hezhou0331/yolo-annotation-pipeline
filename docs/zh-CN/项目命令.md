# 项目命令

日常操作优先使用 `./scripts/atec-app`。以下命令用于环境检查、排错、单场处理和复现实验。

## 1. 常用入口

以下命令均在仓库根目录的终端中运行：

```bash
./scripts/atec-app
./scripts/atec-pipeline --help
./scripts/atec-pipeline status
```

## 2. 环境与资产检查

```bash
./scripts/atec-pipeline doctor
./scripts/atec-pipeline doctor --deep
./scripts/check_all_environments.sh
./scripts/verify_local_assets.sh
./scripts/bootstrap_third_party.sh --check
```

缺失第三方源码时：

```bash
./scripts/bootstrap_third_party.sh --install
```

## 3. 场次初始化、采集和标注

创建场次 Manifest：

```bash
./scripts/atec-pipeline init \
  projects/atec_real <scene> \
  --split train \
  --only-class <class> \
  --scene-class <class>
```

采集命令参数以帮助为准：

```bash
./scripts/atec-pipeline capture --help
```

对已保存场次执行分段、检查缺失 Mask 和完整处理：

```bash
MANIFEST=projects/atec_real/manifests/<scene>_<split>.yaml

./scripts/atec-pipeline segment "$MANIFEST"
./scripts/atec-pipeline checklist \
  projects/atec_real/data/scenes/<class>/<scene>/project_reports/segments.json
./scripts/atec-pipeline run "$MANIFEST"
```

单独打开 Mask 编辑器：

```bash
./scripts/atec-pipeline mask \
  /ABSOLUTE/PATH/rgb/000000.png \
  /ABSOLUTE/PATH/key_masks/<instance>/000000.png
```

## 4. 数据切分与验证

按完整场次准备验证集应优先使用 App。App 实际调用同一个统一 CLI，便于单独复现和 Debug：

```bash
DATASET=projects/atec_real/datasets/atec_yolo11_seg/dataset.yaml

# 自动预览，不修改数据
./scripts/atec-pipeline split "$DATASET" --auto

# 明确指定完整场次并执行
./scripts/atec-pipeline split "$DATASET" \
  --val-scenes <scene_a> <scene_b> \
  --apply
```

底层工具仍可独立调用：

```bash
"${ATEC_YOLO_PY:-$HOME/miniforge3/envs/yolo11/bin/python}" \
  tools/split_dataset_by_scene.py \
  --data "$DATASET" --auto
```

严格验证：

```bash
./scripts/atec-pipeline validate \
  projects/atec_real/datasets/atec_yolo11_seg/dataset.yaml
```

验证要求：

- 只允许 `accepted` 进入正式标签；
- train/val 不共享场次、采集会话或源视频；
- 标签类别 ID 合法；
- 未人工确认的空标签不能冒充负样本；
- 没有真实 test 时不写 `test:`。

## 5. YOLO11-seg 训练

App 训练按钮会调用同一后端。CLI：

```bash
./scripts/atec-pipeline train \
  projects/atec_real/datasets/atec_yolo11_seg/dataset.yaml \
  --init-mode baseline \
  --epochs 100 \
  --batch 4 \
  --device 0 \
  --name <experiment_name>
```

完整可复现入口：

```bash
"${ATEC_YOLO_PY:-$HOME/miniforge3/envs/yolo11/bin/python}" tools/train_yolo11_seg.py \
  --data projects/atec_real/datasets/atec_yolo11_seg/dataset.yaml \
  --model models/yolo11s-seg.pt \
  --init-mode baseline \
  --epochs 100 --batch 4 --imgsz 640 --device 0 --workers 4 \
  --patience 30 --require-project-reports --require-source-ids \
  --project runs/segment --name <experiment_name>
```

当前五类阶段模型：

```text
runs/segment/atec_5class_reviewed_20260826_1744/weights/best.pt
```

该权重只包含 `can`、`watermelon_rind`、`meal_box`、`red_paper_bag`、`blue_bin`。现有七类数据可重新训练七类阶段模型；紫色袋子和沙瓶补齐独立 train/val 后才能训练完整九类模型。

## 6. 实时识别

默认五类阶段模型与外接摄像头：

```bash
./scripts/atec-live-yolo
```

指定模型或摄像头：

```bash
ATEC_YOLO_MODEL=/ABSOLUTE/PATH/best.pt \
ATEC_YOLO_SOURCE=0 \
ATEC_YOLO_CONF=0.25 \
./scripts/atec-live-yolo
```

完整命令：

```bash
"${ATEC_YOLO_PY:-$HOME/miniforge3/envs/yolo11/bin/python}" \
  tools/live_yolo11_seg.py \
  --model /ABSOLUTE/PATH/best.pt \
  --source 0 --conf 0.25 --imgsz 640 --device 0
```

## 7. xcx 候选与 A/B 实验

xcx 主要是检测模型，只能提供候选框或迁移初始化，不能直接生成 YOLO11-seg 像素标签。

生成候选但不覆盖正式 Mask：

```bash
./scripts/atec-pipeline propose \
  <manifest.yaml> \
  projects/atec_real/data/scenes/<class>/<scene>/project_reports/segments.json \
  --output <proposal_dir>
```

人工确认后晋升候选：

```bash
./scripts/atec-pipeline promote /ABSOLUTE/PATH/proposal.json <instance_id>
```

生成 A/B 计划：

```bash
"${ATEC_YOLO_PY:-$HOME/miniforge3/envs/yolo11/bin/python}" \
  tools/run_yolo11_seg_ab.py \
  --data projects/atec_real/datasets/atec_yolo11_seg/dataset.yaml
```

只有在相同 train/val、参数和现场误检测试下，xcx-transfer 稳定优于 baseline，才应替换正式初始化方式。

## 8. 迁移与回归

预览旧场景目录迁移：

```bash
/usr/bin/python3 tools/migrate_scene_layout.py \
  --project-root projects/atec_real
```

确认无冲突后执行：

```bash
/usr/bin/python3 tools/migrate_scene_layout.py \
  --project-root projects/atec_real --apply
```

提交前回归：

```bash
python3 -m py_compile atec_pipeline/*.py tools/*.py
git diff --check
./scripts/atec-pipeline smoke-test
```
