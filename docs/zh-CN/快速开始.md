# 快速开始

## 1. 仓库边界

代码仓库不包含第三方源码、模型权重、ATEC规则PDF和真实RGB-D数据。当前电脑已保留这些本地资产；新电脑需要根据说明恢复。

```bash
./scripts/bootstrap_third_party.sh --check
./scripts/verify_local_assets.sh
./scripts/atec-pipeline doctor
```

缺少第三方源码时：

```bash
./scripts/bootstrap_third_party.sh --install
```

## 2. Conda环境

默认解释器：

```text
orbbec          ~/miniforge3/envs/orbbec/bin/python
foundationpose  ~/miniforge3/envs/foundationpose/bin/python
yolo11          ~/miniforge3/envs/yolo11/bin/python
```

可通过`ATEC_ORBBEC_PY`、`ATEC_FP_PY`、`ATEC_YOLO_PY`覆盖。环境定义位于`environments/`。

## 3. 采集RGB-D

```bash
./scripts/check_orbbec.sh
./scripts/capture_orbbec.sh projects/atec_real/data/scenes/capture_001 \
  --width 640 --height 480 --fps 30 --max-frames 300
```

每个场景至少应包含`rgb/`、`depth/`、相机内参和采集元数据。

## 4. 准备关键Mask

每一自动分段里，每个活跃实例都必须至少有一个可靠关键Mask。声明存在却缺少Mask的物体不能直接当作背景，否则会制造假负样本。

```bash
/home/hezhou/miniforge3/bin/mamba run -n orbbec python tools/draw_first_mask.py \
  --image projects/atec_real/data/scenes/train_bg01/rgb/000000.png \
  --output projects/atec_real/data/key_masks/train_bg01/can_01/000000.png
```

## 5. Dry-run和正式标注

```bash
./scripts/run_auto_annotation_pipeline.sh \
  projects/atec_real/manifests/train_bg01_train.yaml \
  --dry-run --allow-missing-key-masks
```

关键Mask齐全后：

```bash
./scripts/run_auto_annotation_pipeline.sh \
  projects/atec_real/manifests/train_bg01_train.yaml
```

只有所有活跃实例完整、质量状态为`accepted`且无严重Mask冲突的帧进入正式训练集。`review`和`rejected`默认不用于训练。

## 6. Review与训练

重点检查导出目录里的`project_reports/`、`review/`、`dataset.yaml`、`images/`和`labels/`。

```bash
./scripts/train_yolo11_seg.sh \
  projects/atec_real/datasets/atec_yolo11_seg/dataset.yaml 100 4
```

RTX 4060 Laptop 8GB默认从`imgsz=640`、`batch=4`开始；显存不足时先降低batch。
